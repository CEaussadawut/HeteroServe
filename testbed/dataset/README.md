# Device characterisation dataset

The measured knowledge the project delivers: what each board costs per token, per phase, per
quantisation, in a form that transfers to a model the board never ran alone. Every figure is
computed from raw `llama-bench -oe jsonl` samples by a script; nothing here is typed in.

## Columns

`eff_decode_GBps` = model bytes ÷ time per decoded token; `eff_prefill_GFLOPs` = 2 × parameters × prompt
tokens per second. They make one board's cost comparable across models. `rep_range_pct` is the range of
the repetitions of **one** invocation — not the across-run spread, which is ~2 % on these boards.
Flags: `throttled`, `warm-start`, `exit-N`, `n<3`. A flagged row is kept and shown, never dropped.

## Findings

**1. Cost transfers within a quantisation, not always across one.** Model bytes predict decode time
on the Pis to within ±4 % across all three quantisations (`eff_decode_GBps` is nearly constant);
parameters predict prefill on the Pi 4 and the Jetson to within ±3–6 %. The exceptions are real:

| | decode: GB/s across quants | prefill: GFLOP/s across quants |
|---|---|---|
| Pi 5 CPU | 12.0 / 12.1 / 12.9 — **holds** | 296 / 179 / 142 — **fails, 2.1×** |
| Pi 4 CPU | 3.75 / 3.80 / 3.90 — **holds** | 26.1 / 27.6 / 27.1 — holds |
| Jetson CPU | 4.0 / 4.3 / 5.7 — **fails, 1.4×** | 17.3 / 19.2 / 18.7 — holds |
| Jetson Vulkan | 5.3 / 7.6 / 7.9 — Q4_0 is the outlier | 176 / 161 / 174 — holds |

(order Q4_0 / Q4_K_M / Q8_0). **Q3_K_M (2026-09-28)** keeps the decode rule on the Pis (Pi 5 12.0 GB/s, Pi 4 3.68) and
breaks prefill on every board: Pi 5 **88** GFLOP/s (not repacked at this pin), Pi 4 22.4 (−17 % against Q4_K_M), Jetson CPU
15.7 (−18 %), Jetson Vulkan 151 (−6 %). The Jetson also decodes Q3_K_M slower than Q4_K_M in bytes per second (Vulkan
4.37 against 7.64 GB/s, CPU 2.87 against 4.31), so the extra dequantisation costs more than the smaller reads save. The Pi 5's split is its kernels: at this pin llama.cpp repacks Q4_0, Q4_K,
Q6_K and Q8_0 weights into interleaved layouts for AArch64 cores with dotprod (`ggml-cpu/repack.cpp`), and
the Pi 5's Cortex-A76 reports `asimddp`; the Pi 4's A72 does not, and runs the generic kernels. The
Jetson's A57 (no dotprod) decodes compute-bound, so Q8_0's cheaper dequantisation shows. **Rule the engine
follows: take a board's cost from its row at the target model's quantisation.**

**2. The placement engine predicts the 14B pool from these rows alone.** Fed only the TinyLlama Q4_K_M
rows, the 14B's tensor table and the measured link — no pooled data — `validate_placement.py` predicts
every one of the eight measured Pi 5 + Pi 4 splits of Qwen2.5-14B Q4_K_M: **decode within 3.5 % (mean
1.3 %), prefill within 1.7 % (mean 0.9 %)**. The engine's memory caps reproduce the measured boundary (43
blocks on the Pi 5 run; 45 are OOM-killed) and its latency-only rule picks **exactly the measured fastest
split**. Details and the caveats (prefill batch size; the embedding's residency is inferred) are in
`testbed/benchmarks.md`, section "2026-09-27".

**3. A board's cost depends on its role, and on the Pi 5 the difference is phase-dependent.** A board serving as an
RPC worker (`ggml-rpc-server`) gets no repacked weight layouts, because `ggml-rpc.cpp` allocates the default CPU
buffer type. The worker rows (device `cpu-rpc-worker`; `bench_worker_role.sh`, 2026-09-27) measure each Pi as a
loopback worker driven by `llama-bench -ngl 99` on the same board:

| TinyLlama, as a worker vs as the host | prefill | decode |
|---|---:|---:|
| Pi 5 Q4_K_M | **−43 %** (46.3 vs 81.3 t/s) | **+4 %** (18.9 vs 18.1) |
| Pi 5 Q4_0 | −61 % | +4 % |
| Pi 5 Q8_0 | −16 % | −9 % |
| Pi 4 Q4_K_M (control: no repack either way) | +1 % | −1 % |
| Pi 5 Q3_K_M (2026-09-28; Q3_K is not repacked, the file's Q4_K / Q6_K tensors are) | −10 % (36.2 vs 40.1) | +2 % (22.3 vs 21.9) |

Repacking pays off in prefill (batched matmuls), not in decode. So where a board sits in a pool changes its cost per
phase. The engine therefore carries separate host and worker costs (`DeviceProfile.ms_per_layer_*_worker`). The
Jetson's Vulkan worker was measured by the RPC smoke test within 1.2 % (prefill) and 2.5 % (decode) of local.
